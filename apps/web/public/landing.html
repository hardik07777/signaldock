           From event to delivery
          
Three steps. No mystery.

          
Keep the sender fast and let SignalDock handle delivery work in the background.

        

        

          

            
01

            
Create an event

            
Send a target URL and JSON payload. SignalDock validates the request and stores the event before delivery.

            
POST /v1/webhook-events
{
  "targetUrl": "https://…",
  "payload": { "type": "order.created" }
}

          

          

            
02

            
Queue the work

            
The API adds a BullMQ job backed by Redis and returns without waiting for the destination to respond.

            
queue.add("deliverWebhook", {
  eventId: event.id
}, {
  attempts: 5
})

          

          

            
03

            
Inspect and replay

            
Check delivery status and attempt history. Retry a failed event when you are ready to investigate it again.

            
GET /v1/webhook-events/:id
POST /v1/webhook-events/:id/replay

          

        

      

    


    

      

        

           The useful parts
          
Know what happened. Choose what happens next.

          
Delivery visibility and recovery tools, built around the problems that make webhooks harder than they look.

        

        

          

            

            
Inspect every delivery

            
See the target URL, payload, current status, and each recorded attempt without stitching together application logs.

            
Payload JSONAttempt historyStatus tracking

          

          

            

            
Replay without re-creating the event

            
Queue an existing event again after you fix a downstream issue. The original payload and event record stay available for inspection.

            
 Failed event→ Replay queued→New attempt

          

          

            

            
Automatic retries

            
Retry transient failures with exponential backoff and a configurable attempt limit.

          

          

            

            
Forward to an HTTP endpoint

            
Choose a destination URL for each event and let the worker make the outbound request asynchronously.

          

          

            

            Planned
            
Signature verification

            
A planned verification layer to help confirm that incoming requests came from a trusted sender.

          

          

            

            Planned
            
Share with your team

            
Team workspaces and shared debugging are on the roadmap. This demo currently has no user or role management.

          

        

      

    


    

      

        

           Start with one request
          
Send your first event in a few lines.

          
Use the API directly from your service. Replace the sample target URL with a webhook endpoint you control.

        

        

          

            

              
              
              
            

            
          

          
curl -X POST https://signaldock.onrender.com/v1/webhook-events \\
  -H 'Content-Type: application/json' \\
  -d '{
    "targetUrl": "https://webhook.site/your-unique-url",
    "payload": {
      "type": "order.created",
      "orderId": "ord_123"
    },
    "maxAttempts": 5
  }'

          
 Returns as soon as the event is acceptedPOST /v1/webhook-events

        

        
Demo note: use a unique Webhook.site URL to watch a test delivery. The public demo runs on free hosting and is not intended for critical production events.
